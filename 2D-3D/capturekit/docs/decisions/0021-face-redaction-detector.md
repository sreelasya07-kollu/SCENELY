# 0021 Face redaction detector: android.media.FaceDetector now, BlazeFace gated on a licence read
Date 2026-11-16. Status: accepted under ADR 0018 item 11 (best-effort blur in memory before JPEG write, stated in manifest and consent text). Recall/latency table stays "human later" (no labelled set).
- MediaPipe Face Detector offers BlazeFace short-range (128x128, float16; 2.94 ms CPU / 7.41 ms GPU Pixel 6, short-range only benchmarked), full-range and sparse full-range; the page states no licence for code or weights and no training data (VERIFIED: https://developers.google.com/edge/mediapipe/solutions/vision/face_detector). MediaPipe code is Apache-2.0 (VERIFIED: https://raw.githubusercontent.com/google-ai-edge/mediapipe/master/LICENSE).
- The BlazeFace short-range model card PDF (https://storage.googleapis.com/mediapipe-assets/MediaPipe%20BlazeFace%20Model%20Card%20(Short%20Range).pdf) has compressed text streams that the fetch tool could not decode; only a link to apache.org/licenses/LICENSE-2.0.html was extractable. Weights licence and training-data terms are therefore UNVERIFIED; a human must open the PDF.
- android.media.FaceDetector: platform class since API level 1, no model file or extra dependency; needs an RGB_565 bitmap of even width, fixed width/height/maxFaces at construction (VERIFIED: https://developer.android.com/reference/android/media/FaceDetector). Page shows no deprecation notice. Its licence terms and detection quality are UNVERIFIED (BlazeFace is expected to have higher recall on small or non-frontal faces; REPORTED, unmeasured).
- Decision: ship android.media.FaceDetector as the v1 blur detector (no weights-licence exposure, no APK growth), scanned on a downscaled RGB_565 copy; manifest and consent text say "best effort, may miss faces". Adopt MediaPipe BlazeFace (prefer full-range, since a room scan is not selfie distance) as an upgrade only after a human confirms the weights licence in the PDF and fills the recall/latency table.
- Rejected: ML Kit face detection (terms not read, per ledger 2026-11-15); third-party BlazeFace ports (provenance unclear).
- Amendment (2026-11-16, planner delegation per ADR 0018, revisit): fail closed. With redaction_mode=faces, a keyframe whose face detection throws or returns null is NOT written (recorded as dropped_detector_failure in privacy/redaction.json); step 11's "save but flag skipped" is superseded.
- Note: privacy/redaction.json is flushed every 10 entries; after a forced kill it may list a keyframe whose JPEG never landed (status ok, file absent). Validators should treat listed-but-missing files as not written.

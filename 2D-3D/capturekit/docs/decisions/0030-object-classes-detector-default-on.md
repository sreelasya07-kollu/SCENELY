# 0030: More object classes, detector on by default, objects shown live and on review

Status: accepted (2026-11-18), issue RealKarthiksai/2D-3D#2. Amends ADR 0017 ("behind a flag") and ADR 0018 item 6. The "Default on" item is superseded by ADR 0032 (detector off by default until device-verified).
- Classes: core `ObjectClass` ids are recorded in bundles (`/ar/detections`, `/guide/labels`), so they are APPEND-ONLY (pinned by `Understanding.ObjectClassIdsAreFrozen` and the Kotlin `coreNamesMatchTheCoreClassIds`). Added 8 bench, 9 toilet, 10 sink, 11 refrigerator, 12 oven: COCO classes the shipped EfficientDet-Lite0 already predicts (0-based index = COCO id - 1: 14, 69, 80, 81, 78). Added 13 desk, 14 shelf, 15 cabinet, 16 lamp with priors and spoken names but NO detector mapping: COCO 2017 has none of them (nor door / window / mirror; those "???" slots are never predicted). They are reserved for a detector trained on them; swapping the model then only touches `LabelMap.kt`. Microwave / clock / vase were left out: counter- or wall-mounted, and the floor-ray fallback would place them on the floor.
- Doors and windows stay geometry (`OpeningDetector`, Opening kind door/window), not object classes; the UI counts them next to the objects. A model change (Open Images subset or an indoor fine-tune) is NOT made here: no candidate with a verified licence and LiteRT export was found in ADR 0017's search, so this needs its own spike and ADR.
- Schema: no version bump. The `cls` field already holds "a core class id"; new values are additive, validators do not range-check `cls`, and a reader that does not know an id can treat it as unknown. SPEC.md lists the change.
- Default on: the sample app turns the detector on in every build (debug override `setprop debug.capturekit.detector 0`). When the model asset is packaged and no `debug.capturekit.understanding` override is set, the session gets `guide.understanding = 1` (objects + openings, no gap steering: ADR 0018 item 7 still holds), except in the field trial's unguided arm (the no-guidance control: detections are recorded, nothing is lifted or shown). Without the model asset nothing changes (no key, flag-off bundles stay byte-identical). Level 1 makes the session write `/guide/*` (schema 1.3.0, ADR 0028); the app always passes consent keys, so these bundles validate.
- Shown: mini-map footprints in a per-class colour with their spoken name; detector boxes with "class score%" over the camera feed (mapped with ARCore IMAGE_PIXELS -> VIEW, shown 1.5 s then faded, "Boxes" chip toggles them); review screen and review sheet list "2 chairs, 1 sofa, 1 door".
- Risks / open: level 1 adds the NavGrid object layer and surface classification to every real walk, which the real-walk guidance work (docs/WALK_FAILURE_RCA.md) has not been measured with; `setprop debug.capturekit.understanding 0` restores the old behaviour. Latency stays one run per 0.5 s of core time (DetectorScheduler, slower under REDUCE_ML); the < 50 ms per frame target on CPH2381 is human test H19, not measured here. The new classes' priors and the Lite0 accuracy on them are untested on real rooms.

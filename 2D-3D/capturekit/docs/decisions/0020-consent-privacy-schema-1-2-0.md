# 0020: consent and privacy in the manifest, schema 1.2.0

Status: accepted (2026-11-17) under ADR 0018 item 9. Upload needs a verifiable record that consent was given and how faces were handled (ADR 0021).
- Session config keys `consent_version`, `consent_at` (ISO 8601 UTC string, supplied by the shell; the core never reads a clock) and `redaction_mode` (`none`|`faces`). They are written to `session.json` so `recover()` keeps them, and to the manifest as `consent` {version, at} and `privacy` {redaction_mode}. Version and time must be given together; any other mode is rejected at session create.
- `write_manifest` stamps 1.2.0 only when consent or redaction metadata was given; sim, synthetic and imported bundles stay 1.1.0, so goldens and the frozen 1.0.0 fixture are unchanged. Cost: a shell that forgets the keys produces a 1.1.0 bundle that passes; shells enforce consent in the UI (Start blocked), the validator enforces completeness of 1.2.0 bundles.
- Validator (Python, the only place with the manifest): CONSENT_MISSING and REDACTION_MANIFEST_MISSING are ERROR and fire only for schema >= 1.2.0; `faces` without a listed `privacy/redaction.json` also fails. `consent.at` must look like ISO 8601 (else CONSENT_MISSING). The redaction log is untrusted: entries resolving outside `keyframes/` are ignored with REDACTION_ENTRY_BAD_PATH (WARN) and only basenames are echoed. REDACTION_ENTRY_NO_FILE (INFO) covers ADR 0021's flush-every-10 note; entries with status `dropped_detector_failure` are expected to be absent and are not reported. The on-device C++ `validate_semantic` is unchanged (it runs before the manifest exists).
- `privacy/` files get file role `redaction`. `recover()` also carries `/ar/detections` (left out by 1.1.0 work).
